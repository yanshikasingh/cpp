# 6.1 Pointers in C++

Pointers are one of the most important low-level concepts in C++. They
connect **your C++ code to memory**.

This topic includes:

1.  Memory addresses
2.  Pointer declaration
3.  Address-of operator `&`
4.  Dereference operator `*`
5.  Pointer initialization
6.  Pointer arithmetic
7.  Pointer to pointer
8.  Pointers and arrays
9.  Pointers and strings
10. Pointers and functions
11. Function pointers

------------------------------------------------------------------------

# STEP 0 --- Prerequisite Knowledge

You don't need a huge amount of C++ before learning pointers. You need
these concepts:

  -----------------------------------------------------------------------
  Prerequisite                        Why you need it
  ----------------------------------- -----------------------------------
  Variables                           A pointer ultimately points to an
                                      object/value

  Data types                          A pointer has a pointed-to type

  Arrays                              Arrays and pointers are closely
                                      related

  Functions                           Pointers can point to functions

  C-style strings                     Strings are commonly manipulated
                                      through `char*`

  Scope & lifetime                    A pointer can become dangling when
                                      its object dies
  -----------------------------------------------------------------------

### Minimum knowledge

You should understand:

``` cpp
int x = 10;
```

This creates an `int` object named `x` containing `10`.

You should also understand:

``` cpp
void change(int x) {
    x = 20;
}
```

Here `x` is a copy.

And:

``` cpp
int arr[3] = {10, 20, 30};
```

This creates three contiguous `int` objects.

That's enough to start.

------------------------------------------------------------------------

# 1. What Is a Pointer?

A **pointer is an object whose value is the address of another object or
function**.

For example:

``` cpp
int x = 10;

int* p = &x;
```

Conceptually:

``` text
x
┌──────────┐
│    10    │
└──────────┘
    ↑
    │
    │ address
    │
p ──┘
```

The important distinction is:

``` text
x  → actual value
p  → address of x
*p → value stored at the address held by p
```

So:

``` cpp
cout << x;   // 10
cout << p;   // address of x
cout << *p;  // 10
```

A pointer does **not** normally contain the value it points to.

It contains a **location**.

### Where does the concept belong?

Pointers are a **core C++ language feature**.

They are not STL.

They also exist in C.

In fact, pointers are historically fundamental to C and were inherited
heavily by C++.

------------------------------------------------------------------------

# 2. Why Were Pointers Created?

Imagine you have:

``` cpp
int x = 10;
```

You can manipulate `x` directly.

But what if another part of your program needs to know:

> "Where is `x` located in memory?"

Or you want a function to modify the original object rather than a copy?

Or you need dynamically allocated memory?

Or you're working with hardware memory?

Or you need to traverse an array efficiently?

You need some representation of a memory location.

That's where pointers come in.

For example:

``` cpp
void change(int* p)
{
    *p = 100;
}

int x = 10;

change(&x);

cout << x;
```

Output:

``` text
100
```

The function didn't receive `x` itself.

It received the **address of x**.

Therefore it could reach the original object.

------------------------------------------------------------------------

# 3. How Pointers Work Behind the Scenes

Consider:

``` cpp
int x = 10;
int* p = &x;
```

Conceptually, memory might look like:

``` text
Address       Object
─────────────────────
0x1000        x = 10
```

Then:

``` text
p = 0x1000
```

So:

``` text
p
│
│ contains 0x1000
▼
0x1000
┌──────────┐
│    10    │
└──────────┘
    x
```

When you write:

``` cpp
*p
```

C++ interprets that as:

> Go to the object represented by the address stored in `p`.

So:

``` cpp
*p = 50;
```

means:

``` text
p contains address 0x1000
              ↓
        go to 0x1000
              ↓
        change 10 → 50
```

Now:

``` cpp
cout << x;
```

prints:

``` text
50
```

------------------------------------------------------------------------

# 4. Pointer Syntax

## Declaration

``` cpp
int* p;
```

Read this as:

> `p` is a pointer to an `int`.

Other examples:

``` cpp
double* d;
char* c;
float* f;
```

The pointed-to type matters.

``` cpp
int*    → pointer to int
char*   → pointer to char
double* → pointer to double
```

The type tells C++ what kind of object is being accessed and how
operations such as pointer arithmetic should behave.

------------------------------------------------------------------------

# 5. Address-of Operator `&`

The unary `&` operator obtains the address of an object.

``` cpp
int x = 10;

cout << &x;
```

You might see something like:

``` text
0x7ffd1234
```

The exact address is not something you should rely on.

Now:

``` cpp
int* p = &x;
```

means:

``` text
&x → address of x
p  → stores that address
```

------------------------------------------------------------------------

# 6. Dereference Operator `*`

The `*` operator, when applied to a pointer expression, accesses the
object pointed to by that pointer.

``` cpp
int x = 10;
int* p = &x;

cout << *p;
```

Output:

``` text
10
```

And:

``` cpp
*p = 25;
```

changes `x`.

``` text
Before:

x = 10

After:

x = 25
```

### Very important

The symbols `*` and `&` have different meanings depending on context.

``` cpp
int* p;      // declaration: p is pointer
int x = 10;
int* p = &x; // & obtains address
cout << *p;  // * dereferences pointer
```

Don't memorize "`*` means pointer."

More accurately:

> `*` has several uses; in a declaration it contributes to pointer
> declarator syntax, while in an expression it can perform
> indirection/dereference.

------------------------------------------------------------------------

# 7. Pointer Initialization

This is dangerous:

``` cpp
int* p;
```

`p` is an **uninitialized pointer**.

It contains an indeterminate value.

Do not do:

``` cpp
cout << *p;
```

That can result in undefined behavior.

Instead:

``` cpp
int x = 10;
int* p = &x;
```

Or, if it currently points nowhere:

``` cpp
int* p = nullptr;
```

`nullptr` is the modern C++ null pointer value.

Then:

``` cpp
if (p != nullptr)
{
    cout << *p;
}
```

------------------------------------------------------------------------

# 8. `nullptr`

Prefer:

``` cpp
int* p = nullptr;
```

over the old:

``` cpp
int* p = NULL;
```

or:

``` cpp
int* p = 0;
```

`nullptr` has a dedicated C++ type:

``` cpp
std::nullptr_t
```

and is specifically designed to represent a null pointer.

### Critical rule

Never dereference `nullptr`.

``` cpp
int* p = nullptr;

cout << *p; // ❌ Undefined behavior
```

------------------------------------------------------------------------

# 9. Step-by-Step Execution

Consider:

``` cpp
int x = 10;
int* p = &x;

*p = 20;
```

## Before execution

Conceptually:

``` text
Stack

Address       Object
────────────────────
1000          x = 10
```

## Line 1

``` cpp
int x = 10;
```

An `int` object is created.

``` text
1000
┌──────┐
│  10  │
└──────┘
   x
```

## Line 2

``` cpp
int* p = &x;
```

`&x` produces the address of `x`.

Suppose:

``` text
&x = 1000
```

Then:

``` text
p = 1000
```

Conceptually:

``` text
p
┌──────┐
│ 1000 │
└──────┘
   │
   ▼
x
┌──────┐
│  10  │
└──────┘
```

## Line 3

``` cpp
*p = 20;
```

Dereference `p`.

Go to address `1000`.

Modify the object there.

``` text
Before:

x = 10

After:

x = 20
```

------------------------------------------------------------------------

# 10. Level 1 --- Basic Example

``` cpp
#include <iostream>
using namespace std;

int main()
{
    int x = 10;

    int* p = &x;

    cout << x << '\n';
    cout << *p << '\n';

    *p = 50;

    cout << x << '\n';
}
```

Output:

``` text
10
10
50
```

The key relationship:

``` text
x       → object
&x      → address
p       → stores address
*p      → object reached through address
```

------------------------------------------------------------------------

# 11. Level 2 --- Practical Example

Pointers allow a function to modify an existing object.

``` cpp
void increment(int* p)
{
    ++(*p);
}

int main()
{
    int value = 10;

    increment(&value);

    cout << value;
}
```

Output:

``` text
11
```

Execution:

``` text
value = 10

&value
   ↓
increment()
   ↓
p contains address of value
   ↓
*p
   ↓
value
   ↓
10 → 11
```

This is one of the classic uses of pointers.

------------------------------------------------------------------------

# 12. Level 3 --- Dynamic Memory

Pointers are also involved in dynamic storage.

``` cpp
int* p = new int(42);

cout << *p;

delete p;
p = nullptr;
```

Conceptually:

``` text
Stack                     Heap

p ─────────────────────► [42]
```

`p` is stored as an object itself, while the dynamically allocated `int`
is obtained from dynamic storage.

After:

``` cpp
delete p;
```

the allocated object no longer exists.

Therefore:

``` cpp
p = nullptr;
```

is useful to avoid leaving `p` containing the former address.

### Modern C++ warning

In modern C++, avoid manually using `new`/`delete` in ordinary
application code when RAII/smart pointers can manage ownership.

For example:

``` cpp
auto p = std::make_unique<int>(42);
```

is generally preferable when you actually need dynamic ownership.

------------------------------------------------------------------------

# 13. Pointer Arithmetic

Suppose:

``` cpp
int arr[] = {10, 20, 30, 40};

int* p = arr;
```

Conceptually:

``` text
1000 → 10
1004 → 20
1008 → 30
1012 → 40
```

Assume `int` occupies 4 bytes.

Then:

``` text
p       → 1000
p + 1   → 1004
p + 2   → 1008
p + 3   → 1012
```

`p + 1` does **not** mean address + 1 byte.

It means:

> move to the next `int` object.

The compiler knows the pointed-to type.

------------------------------------------------------------------------

# 14. Pointer Arithmetic Example

``` cpp
int arr[] = {10, 20, 30};

int* p = arr;

cout << *p << '\n';

p++;

cout << *p << '\n';

p++;

cout << *p << '\n';
```

Output:

``` text
10
20
30
```

Conceptually:

``` text
p
↓
[10][20][30]
```

After:

``` cpp
p++;
```

`p` points to the next element.

------------------------------------------------------------------------

# 15. What Pointer Arithmetic Is Actually Allowed?

For an array:

``` cpp
int arr[3] = {10, 20, 30};
```

You can have:

``` cpp
int* p = arr;

p++;
p += 2;
p - 1;
```

You can also obtain a pointer **one past the end**:

``` cpp
int* end = arr + 3;
```

But you cannot dereference it:

``` cpp
*end; // ❌ Undefined behavior
```

This concept is important because C++ iterators often follow the same
`[begin, end)` model.

------------------------------------------------------------------------

# 16. Pointers and Arrays

This is one of the most important relationships in C++.

``` cpp
int arr[3] = {10, 20, 30};
```

In many expressions, `arr` converts to a pointer to its first element:

``` cpp
arr
```

behaves like:

``` cpp
&arr[0]
```

Therefore:

``` cpp
int* p = arr;
```

is valid.

Then:

``` cpp
*p       // arr[0]
*(p + 1) // arr[1]
*(p + 2) // arr[2]
```

So:

``` cpp
arr[i]
```

is closely related to:

``` cpp
*(arr + i)
```

This is why arrays and pointers are so closely connected.

------------------------------------------------------------------------

# 17. But Arrays Are NOT Pointers

This is a common beginner misconception.

``` cpp
int arr[5];
```

`arr` is an **array**.

It is not a pointer.

But in many expressions, it undergoes an **array-to-pointer
conversion**.

For example:

``` cpp
int* p = arr;
```

Here `arr` converts to a pointer to its first element.

But:

``` cpp
sizeof(arr)
```

does not behave like:

``` cpp
sizeof(p)
```

For example:

``` cpp
int arr[5];

cout << sizeof(arr);
```

If `int` is 4 bytes, this is:

``` text
20
```

Whereas:

``` cpp
int* p = arr;

cout << sizeof(p);
```

might be:

``` text
8
```

on a typical 64-bit system.

The pointer stores an address; the array contains its elements.

------------------------------------------------------------------------

# 18. Pointer to Pointer

A pointer can itself have an address.

``` cpp
int x = 10;

int* p = &x;

int** pp = &p;
```

Conceptually:

``` text
pp
 │
 ▼
 p
 │
 ▼
 x
10
```

More explicitly:

``` text
pp
│
│ contains address of p
▼
┌─────────┐
│ address │
│ of p    │
└─────────┘
     │
     ▼
p
┌─────────┐
│ address │
│ of x    │
└─────────┘
     │
     ▼
x
┌─────────┐
│   10    │
└─────────┘
```

Then:

``` cpp
*pp
```

gives `p`.

And:

``` cpp
**pp
```

gives `x`.

Therefore:

``` cpp
cout << **pp;
```

prints:

``` text
10
```

------------------------------------------------------------------------

# 19. Why Pointer-to-Pointer Exists

A common use is modifying a pointer itself through a function.

``` cpp
void allocate(int** p)
{
    *p = new int(42);
}
```

But modern C++ often has safer abstractions for ownership.

Pointer-to-pointer is particularly relevant when interfacing with:

-   C APIs
-   low-level libraries
-   legacy code
-   APIs that modify caller-owned pointers

------------------------------------------------------------------------

# 20. Pointers and Strings

A C-style string is traditionally a sequence of characters ending with:

``` cpp
'\0'
```

Example:

``` cpp
char str[] = "Hello";
```

Conceptually:

``` text
H  e  l  l  o  \0
```

A pointer can traverse it:

``` cpp
char* p = str;

while (*p != '\0')
{
    cout << *p;
    ++p;
}
```

Output:

``` text
Hello
```

Here:

``` text
p       → current character address
*p      → current character
++p     → next character
```

------------------------------------------------------------------------

# 21. String Literal vs Character Array

This distinction matters.

``` cpp
char str[] = "Hello";
```

creates an array containing its own characters.

But:

``` cpp
const char* p = "Hello";
```

points to a string literal.

You must not attempt:

``` cpp
p[0] = 'X'; // ❌ Undefined behavior
```

String literals are not modifiable.

For modern C++ code, prefer:

``` cpp
std::string
```

when you need an ordinary mutable string.

------------------------------------------------------------------------

# 22. Pointers and Functions

Pointers can be passed to functions.

``` cpp
void change(int* p)
{
    *p = 100;
}

int main()
{
    int x = 10;

    change(&x);

    cout << x;
}
```

Output:

``` text
100
```

The pointer allows the function to access the original object.

------------------------------------------------------------------------

# 23. Pointer vs Reference

This is extremely important in modern C++.

### Pointer

``` cpp
void change(int* p)
{
    *p = 100;
}
```

Call:

``` cpp
change(&x);
```

### Reference

``` cpp
void change(int& x)
{
    x = 100;
}
```

Call:

``` cpp
change(x);
```

References are often cleaner when the function requires an existing
object.

Pointers are useful when:

-   "no object" is a valid state
-   pointer arithmetic is needed
-   interacting with low-level APIs
-   representing optional/nullable addresses
-   dealing with certain data structures

------------------------------------------------------------------------

# 24. Function Pointers

A pointer doesn't have to point to data.

It can point to a function.

Consider:

``` cpp
void hello()
{
    cout << "Hello";
}
```

A pointer to this function can be declared:

``` cpp
void (*p)() = hello;
```

Read it carefully:

``` text
void
   (*p)
      ()
```

means:

> `p` is a pointer to a function that takes no parameters and returns
> `void`.

Then:

``` cpp
p();
```

calls the function.

------------------------------------------------------------------------

# 25. Function Pointer Example

``` cpp
#include <iostream>
using namespace std;

void hello()
{
    cout << "Hello\n";
}

void bye()
{
    cout << "Bye\n";
}

int main()
{
    void (*func)() = hello;

    func();

    func = bye;

    func();
}
```

Output:

``` text
Hello
Bye
```

The pointer can refer to different functions with the same signature.

------------------------------------------------------------------------

# 26. Practical Function Pointers

Function pointers allow behavior to be selected dynamically.

For example:

``` cpp
int add(int a, int b)
{
    return a + b;
}

int multiply(int a, int b)
{
    return a * b;
}

int calculate(int a, int b, int (*operation)(int, int))
{
    return operation(a, b);
}
```

Then:

``` cpp
cout << calculate(5, 3, add) << '\n';
cout << calculate(5, 3, multiply) << '\n';
```

Output:

``` text
8
15
```

This is an early form of **passing behavior as data**.

Modern C++ often uses:

``` cpp
std::function
```

or templates/lambdas instead, depending on the situation.

------------------------------------------------------------------------

# 27. Common Mistakes

## Mistake 1 --- Dereferencing an uninitialized pointer

``` cpp
int* p;

cout << *p; // ❌
```

### Problem

`p` does not point to a valid object.

Dereferencing it produces undefined behavior.

### Correct

``` cpp
int x = 10;

int* p = &x;

cout << *p;
```

------------------------------------------------------------------------

# 28. Mistake 2 --- Dereferencing `nullptr`

``` cpp
int* p = nullptr;

cout << *p; // ❌
```

### Correct

``` cpp
if (p)
{
    cout << *p;
}
```

------------------------------------------------------------------------

# 29. Mistake 3 --- Dangling Pointer

``` cpp
int* p;

{
    int x = 10;
    p = &x;
}

cout << *p; // ❌
```

Why?

`x` stops existing when its scope ends.

So:

``` text
p ─────X────► destroyed object
```

`p` is now a **dangling pointer**.

The pointer value might still contain the old address, but the object no
longer exists.

------------------------------------------------------------------------

# 30. Mistake 4 --- Returning Address of a Local Variable

``` cpp
int* getValue()
{
    int x = 10;

    return &x; // ❌
}
```

After the function returns:

``` text
x
```

no longer exists.

The returned pointer is dangling.

------------------------------------------------------------------------

# 31. Mistake 5 --- Out-of-Bounds Pointer Arithmetic

``` cpp
int arr[3] = {10, 20, 30};

int* p = arr;

cout << *(p + 5); // ❌
```

There is no valid `int` there.

This is undefined behavior.

------------------------------------------------------------------------

# 32. Mistake 6 --- Memory Leak

``` cpp
int* p = new int(10);

p = new int(20);
```

The first allocation has become unreachable.

You lost the address needed to release it.

That's a memory leak.

Modern C++ solution:

``` cpp
auto p = std::make_unique<int>(10);

*p = 20;
```

RAII automatically handles destruction.

------------------------------------------------------------------------

# 33. Mistake 7 --- Use After Delete

``` cpp
int* p = new int(10);

delete p;

cout << *p; // ❌
```

The object has already been destroyed.

`p` is dangling.

Safer pattern:

``` cpp
delete p;
p = nullptr;
```

But preferably use an owning RAII abstraction instead of manually
managing the allocation.

------------------------------------------------------------------------

# 34. Edge Cases You Must Know

The major dangerous states are:

``` text
Uninitialized pointer
        ↓
   unknown address

nullptr
        ↓
   points nowhere

Valid pointer
        ↓
   points to live object

Dangling pointer
        ↓
   points to destroyed object

Out-of-bounds pointer
        ↓
   outside permitted array range
```

These are not interchangeable.

------------------------------------------------------------------------

# 35. Pointer Lifetime vs Object Lifetime

This is a deeper concept.

Suppose:

``` cpp
int* p;

{
    int x = 10;
    p = &x;
}
```

The **pointer `p` still exists**.

But the **object `x` doesn't**.

Therefore:

``` text
Pointer lifetime       Object lifetime

      p                     x
      │                     │
      │                     │
      └─────────────┐       │
                    │       │
                    ▼       ▼
                  pointer   destroyed
                  remains
```

A pointer's existence does not guarantee that the object it points to
exists.

This distinction is fundamental to understanding memory bugs.

------------------------------------------------------------------------

# 36. Performance

Basic pointer operations are generally constant time:

``` cpp
*p
```

→ `O(1)`

``` cpp
p++
```

→ `O(1)`

``` cpp
p + n
```

→ `O(1)`

But pointer operations themselves aren't automatically "faster."

For example:

``` cpp
arr[i]
```

and:

``` cpp
*(arr + i)
```

normally have equivalent underlying access semantics.

Don't write pointer-heavy code just because pointers "are faster."

Use them when their semantics are appropriate.

------------------------------------------------------------------------

# 37. Pointer Arithmetic and Cache Performance

Pointers become especially useful when working with contiguous memory.

Example:

``` cpp
int arr[1000000];
```

The elements are stored contiguously.

This allows CPUs to take advantage of:

-   spatial locality
-   cache lines
-   hardware prefetching

But the performance benefit comes primarily from **memory layout/access
patterns**, not from the `*` syntax itself.

This is an important professional distinction.

# 38. Related C++ Concepts

``` text
                         Pointers
                            │
          ┌─────────────────┼──────────────────┐
          │                 │                  │
       References         Arrays            Functions
          │                 │                  │
          │                 │                  │
     pass by reference   pointer arithmetic  function pointers
          │                 │                  │
          └────────────┬────┴──────────────────┘
                       │
                 Memory & Lifetime
                       │
             ┌─────────┼─────────┐
             │         │         │
           Stack      Heap     Ownership
             │         │         │
             └─────────┼─────────┘
                       │
                    RAII
                       │
                Smart pointers
```

The important connections are:

### Pointer → Array

Arrays provide contiguous objects, making pointer arithmetic meaningful.

### Pointer → Function

A function can be represented through a function pointer and passed as
behavior.

### Pointer → Lifetime

Pointers can outlive the objects they point to, producing dangling
pointers.

### Pointer → Dynamic memory

Dynamic allocation returns addresses that can be stored in pointers.

### Pointer → Smart pointers

Modern C++ uses smart pointers to express ownership and automatically
manage resources.

------------------------------------------------------------------------

# 39. What Beginners Usually Miss

## 1. A pointer is not the object

``` cpp
int x = 10;
int* p = &x;
```

There are two objects here:

``` text
x → int object
p → pointer object
```

------------------------------------------------------------------------

## 2. Pointer size is not related directly to pointed-to type size

Usually:

``` cpp
sizeof(int*) == sizeof(double*)
```

on a particular platform.

For example, both might be 8 bytes.

But:

``` cpp
sizeof(int)
```

could be 4.

The pointer stores an address; it doesn't store the entire object.

------------------------------------------------------------------------

## 3. Pointer type affects arithmetic

``` cpp
int* p;
```

`p + 1` moves by one `int`.

``` cpp
double* p;
```

`p + 1` moves by one `double`.

------------------------------------------------------------------------

## 4. `nullptr` is not an invalid pointer value in itself

It is specifically the null pointer value.

It means:

> this pointer does not point to an object/function.

Dereferencing it is the problem.

------------------------------------------------------------------------

# 40. Expert-Level Insight --- Pointer ≠ Ownership

This is one of the most important modern C++ ideas.

Having:

``` cpp
int* p;
```

does **not** tell you whether `p` owns the object.

For example:

``` cpp
int x = 10;
int* p = &x;
```

`p` does not own `x`.

`x` will be destroyed according to its own lifetime.

Compare:

``` cpp
auto p = std::make_unique<int>(10);
```

Now `p` represents **ownership** of the dynamically allocated object.

Therefore professionals distinguish:

``` text
Pointer
   ↓
How do I access this object?

Ownership
   ↓
Who is responsible for destroying this object?
```

These are different questions.

------------------------------------------------------------------------

# 41. Modern C++ Perspective

Raw pointers are still important.

They are **not obsolete**.

But manually managing memory with raw pointers is usually discouraged.

  Aspect                  Raw Pointer    Modern C++
  ----------------------- -------------- ----------------------------
  Non-owning access       Excellent      Raw pointer/reference
  Ownership               Manual         `unique_ptr`, `shared_ptr`
  Safety                  Lower          Higher with RAII
  Pointer arithmetic      Yes            Raw pointers/iterators
  Dynamic ownership       `new/delete`   Smart pointers
  C API interaction       Essential      Often unavoidable
  Low-level programming   Essential      Essential

### Good modern approach

For non-owning access:

``` cpp
void print(const int* p)
{
    if (p)
        cout << *p;
}
```

For ownership:

``` cpp
auto p = std::make_unique<int>(42);
```

For shared ownership:

``` cpp
auto p = std::make_shared<int>(42);
```

But don't automatically use smart pointers everywhere.

If an object already has clear ownership elsewhere, a raw pointer or
reference can be the correct **non-owning view**.

------------------------------------------------------------------------

# 42. Pointer vs Reference

A useful professional comparison:

  Feature                            Pointer             Reference
  ---------------------------------- ------------------- -----------------
  Can be null                        Yes                 No, normally
  Can be reseated                    Yes                 No
  Requires dereference               Yes                 No
  Supports pointer arithmetic        Yes                 No
  Represents an address explicitly   Yes                 Not directly
  Good for optional object           Yes                 No
  Good for required parameter        Often unnecessary   Often preferred

Example:

``` cpp
int x = 10;

int* p = &x;
int& r = x;
```

Then:

``` cpp
*p = 20;
r = 30;
```

Both modify `x`.

But they communicate different intentions.

# 43. A Very Important Pointer Rule

When you see:

``` cpp
T* p;
```

ask three questions:

### 1. What type does it point to?

``` cpp
T
```

### 2. Is it currently valid?

``` text
nullptr?
valid object?
dangling?
uninitialized?
```

### 3. Who owns the object?

``` text
nobody?
stack object?
another object?
unique_ptr?
shared_ptr?
external system?
```

This mindset is much more useful than simply knowing pointer syntax.

# 44. Complete Example Combining Concepts

``` cpp
#include <iostream>
using namespace std;

void modify(int* p)
{
    if (p)
        *p += 10;
}

int main()
{
    int arr[] = {10, 20, 30};

    int* p = arr;

    cout << *p << '\n';

    ++p;

    cout << *p << '\n';

    modify(p);

    cout << *p << '\n';

    int** pp = &p;

    cout << **pp << '\n';
}
```

Output:

``` text
10
20
30
30
```

Let's understand the relationships:

``` text
arr
 │
 ▼
[10] [20] [30]
       ▲
       │
       p
       │
       ▼
      *p = 30

pp
 │
 ▼
 p
 │
 ▼
30
```

This single example combines:

-   arrays
-   pointers
-   pointer arithmetic
-   dereferencing
-   function parameters
-   pointer-to-pointer

# 45. Final Mental Model

Don't think:

> "A pointer is a special variable that stores a memory address."

That's correct, but incomplete.

Think:

> **A pointer is a typed way to refer indirectly to an object or
> function through its address.**

And remember this chain:

``` text
OBJECT
  │
  │ &
  ▼
ADDRESS
  │
  │ stored in
  ▼
POINTER
  │
  │ *
  ▼
OBJECT
```

For example:

``` cpp
int x = 10;

int* p = &x;
```

Mental model:

``` text
             &x
              │
              ▼
       ┌─────────────┐
       │   address   │
       └─────────────┘
              ▲
              │
              │ stored in
              │
             p
              │
              │ *
              ▼
       ┌─────────────┐
       │     10      │
       └─────────────┘
              x
```

The **four things you should never confuse** are:

``` text
x       → the object/value
&x      → address of x
p       → pointer containing that address
*p      → object/value reached through p
```

Once this becomes natural, the rest of pointers becomes much easier:

``` text
Pointers
   │
   ├── &       → obtain address
   │
   ├── *       → access pointed object
   │
   ├── + / -   → move across contiguous objects
   │
   ├── **      → pointer to pointer
   │
   ├── arrays  → contiguous memory + pointer arithmetic
   │
   ├── char*   → traditional C-style strings
   │
   ├── T*      → pass/access existing objects
   │
   └── (*f)()  → function pointer
```

### The one rule to remember

**A pointer is useful because it separates *where an object is* from
*the object itself*.**

That single idea explains why pointers are useful for arrays, functions,
dynamic memory, data structures, system programming, and low-level C++.
